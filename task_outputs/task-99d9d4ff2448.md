# PTL 硬件构成 深度调研

## 一句话概述

PTL（Pick-to-Light / Put-to-Light，电子标签拣选/播种系统）本质上是"一堆挂在货架上的带按钮的小屏幕"，硬件由 **标签节点 + 现场总线/网关 + 电源分配 + 上位机接口** 四层组成，选型的核心矛盾是：**通信稳定性、成本、可维护性、和 WMS/WCS 集成难度**之间的取舍。

---

## 一、核心概念 / 技术栈

**标签节点（Tag / Module）**
- 显示单元：LED 数码管（3–5 位）或 OLED/E-ink 段码屏，显示数量、货位、指令码
- 指示单元：高亮 LED（红/绿/黄/多色），负责"点亮此位"
- 交互单元：确认按钮（+/−/OK）、光电传感器（手伸入触发）、蜂鸣器
- MCU：STM32/GD32/ESP32/HC32 级别，负责协议解码 + 驱屏

**总线 / 通信层**
- 有线：RS-485（最主流）、CAN、Ethernet/IP、EtherCAT、Modbus RTU、专有半双工总线
- 无线：2.4G 私有协议、BLE Mesh、LoRa、Wi-Fi、Zigbee
- 拓扑：手拉手菊花链（daisy chain）/ 星型 / 树状 / Mesh

**网关 / 控制器（Concentrator / Gateway）**
- 下行接总线，上行接以太网/OPC-UA/HTTP/MQTT
- 常见形态：工控盒（x86 + Linux）、PLC 模块、嵌入式 Cortex-A（RK3568/i.MX6）

**供电与机械**
- 集中供电（DC 24V/48V 通过总线并行送电，POE-like）或分段供电
- 磁吸/卡扣/滑轨式安装底座，配合货架横梁

**上位机接入**
- WMS（仓库管理）下发拣选任务
- WCS（仓库控制系统）负责设备编排
- 常见协议：TCP Socket 自定义包、OPC-UA、REST、Kafka、MQTT

## 三、最佳实践 / 踩过的坑

**电源与地**
- RS-485 菊花链**必须共地**，否则长距离下差分电平被抬起，随机丢包
- 24V 供电末端压降别忽略：50 米 0.5mm² 线径 + 200 个标签，末端可能只剩 19V，MCU 上电复位循环
- 每一段总线加**TVS 二极管 + 磁环**，仓库里叉车电机启停是主要 EMI 源

**通信协议**
- 自研协议一定要设计**心跳 + 序号 + CRC + 重传**，不要相信"485 应该不会丢"
- 广播地址不要滥用：一次广播 500 个节点回 ACK 会瞬间打满总线
- **地址烧录方式**：出厂预烧写 vs 现场按钮学习 vs 拓扑自动分配 —— 后两者对运维友好但增加固件复杂度

**机械/物理层**
- 显示屏一定要选**宽视角 + 高亮度**（>500 nits），弯腰仰视看不清是最常见客诉
- 按钮**寿命 100 万次以上**，别用消费级微动开关
- 标签外壳做到 **IP54 起步**，冷库/食品库要 IP65
- 磁吸底座比螺丝好维护，但要注意叉车震动下的位移

**上位机集成**
- WMS 下发指令建议异步 + 幂等：网络抖动重发不会造成重复拣选
- 灯亮 → 拣货 → 确认按钮 → 回传，这个闭环的**超时策略**要和业务方确认（超时是报警、跳过、还是转人工）
- 日志要能追溯到"哪个标签在几点几分被哪个 SKU 点亮"，出错时是唯一的证据

**采购/BOM**
- 单店/单仓样机阶段别贪便宜买白牌，协议文档缺失能拖死项目
- 询价一定要含**备件价 + MOQ + 交期**，PTL 节点是消耗品，一年 3–5% 损耗算正常

## 四、适用场景 / 不适用场景

**适合上 PTL**
- 高频次、小批量、多 SKU 拣选（电商、医药、汽配、图书）
- 需要培训成本极低的场景（新员工 30 分钟上手）
- 播种式分拣（一单多品 → 多单一品）
- 与 AGV/输送线联动的"到人拣选"工作站

**不适合 / 性价比差**
- SKU 极少（<50 种）：条码枪 + 屏幕更划算
- SKU 极多且低频（>10 万种，长尾）：RF 手持 + 语音拣选（Pick-to-Voice）更灵活
- 冷冻库 (-25°C 以下)：LCD 会失效，只能选专用低温 LED，成本翻倍
- 布局频繁变动的仓库：无线方案尚可，有线 PTL 改造成本高
- 拣选路径本身就短（<10 米货架）：ROI 撑不起来
