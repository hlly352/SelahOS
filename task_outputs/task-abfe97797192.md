# PTL 深度调研（LifeOS 语境）

## 一句话概述
PTL（Praise The Lord，赞美 / 感恩记录）在 LifeOS/SelahOS 语境里，本质是**一个结构化的感恩与见证记录模块**——把散落在祷告、日记、聊天里的"赞美/感恩"事件收拢成可查询、可回顾、可导出的数据流，为长期属灵回顾提供素材密度。

## 核心概念 / 技术栈

**概念层**
- **Praise Event**：一次具体的赞美事件，含时间、场景、触发事件、经文引用（可选）、情绪标签
- **Testimony**：多个 Event 聚合成的叙事片段，可跨天/跨月
- **Selah Rhythm**：日/周/月固定回顾节奏（Selah = 停下来默想）
- **Reference Anchor**：经文、诗歌、书摘引用，作为 Event 的支撑材料
- **Aggregation**：Event → Testimony → 年鉴的自底向上聚合

**技术栈候选**
- 存储：SQLite / Markdown+YAML 前言 / Notion API / Obsidian vault
- 输入：CLI（Hermes skill）/ iOS 快捷指令 / Telegram bot（你 gateway 已在）/ Whisper 语音转写
- 检索：SQLite FTS5 / 向量嵌入（相似恩典召回）/ 标签
- 回顾：cron 定时 + LLM 生成周/月报
- 输出：Markdown 报告 / 打印版年鉴 / 分享卡片

## 主流方案对比

| 方案 | 存储 | 输入门槛 | 检索 | 隐私 | LifeOS 集成度 | 适合谁 |
|---|---|---|---|---|---|---|
| 纯 Markdown（Obsidian/日记） | 本地文件 | 低 | 中（dataview） | 高 | ★★★★★ | 已有 Obsidian 习惯 |
| SQLite + CLI 自建 | 本地 DB | 中 | 高（结构化查询） | 高 | ★★★★☆ | 有 Hermes 基础、想量化 |
| Notion 数据库 | 云端 | 低 | 中 | 中 | ★★★☆☆ | 想跨设备、不介意云 |
| Telegram Bot + 日志 | 消息流 | 极低 | 低（除非索引） | 中 | ★★★★☆（gateway 已就位） | 想"随手说一句" |
| Whisper 语音转写 | 音频+文本 | 极低 | 中 | 高（本地转） | ★★★☆☆ | 通勤、散步即时记录 |

**推荐组合**：Markdown（真源）+ SQLite 索引层（查询）+ Telegram bot（输入）——你的 gateway 已经把最难的输入通道解决了。

## 最佳实践 / 踩过的坑

**好的实践**
- **双通道输入**：随手一句（低门槛）+ 每周一次结构化补全（补标签、补经文），别指望一次就写完整
- **Selah 节律优先于每日打卡**：固定周日晚 20 分钟回顾，比强推每日更能坚持
- **引用锚点摘抄原文一小段**，别只留经文编号——半年后你不会记得当时为何被那节触动
- **LLM 起草 + 人工润色**：Event → Testimony 的聚合让模型做草稿，你只做编辑
- **真源在 Markdown**：DB/索引可以随时重建，纯文本才是能穿越十年的载体

**踩过的坑**
- **打分/评级化**：给恩典打 1-5 分会让记录变功利，很快写不下去
- **只用云服务**：Notion/Google 涨价或断网，几年记录被绑架
- **过度分类**：开局就设 20 个标签，最后一个都不用；从 3-5 个开始长
- **只写"大恩典"**：忽略日常小事，年终回顾反而空洞——素材密度靠日常
- **忘了导出/归档**：数据在，但没有可读年鉴，几年后自己都不翻
- **过早上向量检索**：30 条数据里全文搜完全够用，先别引入 embedding 复杂度

## 适用场景与不适用场景

**适用**
- 有稳定灵修/感恩习惯，想把散落记录归拢
- SelahOS/LifeOS 这种把生活当系统来经营的项目
- 想给自己/家人做年度或十年回顾
- 牧养/小组场景，需要沉淀见证素材

**不适用**
- 属灵低谷或抑郁期：此时任何系统摩擦都是负担，回到纸笔或语音就好
- 面向公众分享/传福音的内容生产：那是另一套发布工作流
- 多人协作共写场景：这个模块的核心是个人性
